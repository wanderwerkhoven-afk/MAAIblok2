## Logbook

> **Fill-in instructions**:
>
> This is the entry point to your logbook. A logbook allows students to record the project's progress. 
> Here you should register:
> 1. Schedules and progress summaries.
> 2. Designs and diagrams
> 3. Research documentation
> 4. Feedback you have received from coaches, lecturers, fellow students, etc.
>
> Feel free to organise this section according to your preference, for example, adding links to other documents. 
> 
> Your coach visits the logbook to get updates on the project's progress. Thus, ensure your logbook is well-organised and readable, containing a table of contents, and each component in the log has which team members worked on it. Eventually, you can copy parts of the logbook into your report.
> 
> This file follows the markdown language standard to render text. You can also use an extended markdown compatible with gitlab to add table of contents, draw diagrams, colored code-blocks an so on. Take a look at the [documentation](https://docs.gitlab.com/ee/user/markdown.html) to find out more.

## Report

>**Fill-in instructions**:
>
>A report should be delivered at the end of the block. This report should contain the most relevant choices, results, and discussions. The student manual, section 4, has more information about the required content and outline. 
> Use the *AIMRaD* style, covered in the mini-symposium classes. The document should not exceed ten pages and follow the double-column style of IEEE. 
>[Here, you can find the template](https://www.ieee.org/conferences/publishing/templates.html) available both in LaTeX and Word.
>
>Please add a link to the PDF file versioned in this repository.
